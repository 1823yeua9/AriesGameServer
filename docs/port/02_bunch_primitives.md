# 02 - Bunch primitives and builder catalog

Reference for the Rust `bits` and `rep` crates. Covers `local_backend/range_server_bunch.py` (1611 lines, every definition), the parts of `range_udp_transform.py` and `range_udp_handshake.py` that the bunch frame depends on (`transform_short_packet`, `wrap_gcm`, frame assembly), and the content transform. Every bit width, constant and GUID below is copied from the Python with its `file:line`. Every hex vector in this file was generated by importing the Python modules offline (no responder, no client) and pasting the output mechanically; the Rust golden tests should assert byte equality and bit count against them.

File abbreviations: `rsb` = `range_server_bunch.py`, `rut` = `range_udp_transform.py`, `hs` = `range_udp_handshake.py`, `rci` = `range_client_input.py`. "PROD" means reached on the production flag set (launch.ps1 lines 166-192 plus launch_range.py lines 29-53, 214-219). "DEAD" means only reachable through a flag or env var that production does not set.

## 0. Runtime notes from the user

- The Rust external server runs at **128 ticks per second** and **allocates a console with logging**. Nothing in this layer depends on tick rate: every builder here is a pure function of its arguments. The Python never reports a server frame time (packet header bit `bHasServerFrameTime` is always written 0, section 7.2), and the only frame-time RPC (`build_server_performance_rpc_payload`, 7.8125 ms = 1/128 s) is DEAD with a known-wrong field index (rsb:969-977). Do not send either without a new live verification.
- Logging: the Python logs each sent setup bunch's encoded content payload as hex (for example `event["game_state_bool_probe_payload"] = encoded_payload.hex()`, hs:2405) and the frame length. Logging `channel, reliable sequence, body bits, encoded payload hex, frame length` per sent bunch in the Rust console makes the LIVE vectors in this file directly comparable.

## 1. Bit model and `BitWriter` (rsb:16-75)

### 1.1 Model

`BitWriter` holds an unbounded integer `value` and `bit_count`. Bit `i` of the stream is bit `i` of `value`. `to_bytes()` returns `value` as little-endian bytes of length `ceil(bit_count/8)`; unused high bits of the last byte are 0. So the stream is LSB-first within each byte, bytes in order. A Rust `BitWriter` over `Vec<u8>` that writes each value LSB-first at the current bit position is equivalent.

Notation used in the rest of this document:

```text
bN(v)     append_bits(v, N)              N raw bits of v, LSB first
pk(v)     append_packed_uint(v)          7-bit groups, 8 bits per group
si(v,M)   append_serialize_int(v, M)     UE SerializeInt, value-dependent width
fs("s")   append_fstring_ascii("s")      b32(len+1), bytes, 00
raw(x,n)  append_payload(x, n)           n bits of little-endian x
enc(P,a)  encode_short_actor_rep_payload(P.bytes, P.bits, 0, a)   same bit count as P (section 5)
```

### 1.2 `append_bits(value, width)` (rsb:21-25)

Appends `width` bits of `value`, LSB first. Raises if `width < 0`, `value < 0` or `value >= 1 << width`. `width == 0` with `value == 0` is legal and appends nothing.

### 1.3 `append_packed_uint(value)` (rsb:27-35)

### 1.4 `append_serialize_int(value, value_max)` (rsb:37-60)

UE `FBitWriter::SerializeInt`. Requires `0 <= value < value_max` and `value_max <= 1 << 32`. Algorithm (copy exactly, use u64):

```text
new_value = 0; mask = 1
while new_value + mask < value_max and mask < 2^32:
    bit = (value & mask) != 0
    b1(bit); if bit: new_value += mask
    mask <<= 1
returns number of bits written
```

The width depends on the value, not just on `value_max`: `si(127,179)` is 7 bits but `si(128,179)` is 8 bits; `si(0,1)` writes 0 bits. Used for RPC field indices (`si(field_index, class_max_index + 1)`) and for the close reason (`si(reason, 15)`). The 13-bit bunch size is written as a raw `b13` (rsb:1602); for values below 8192 that is bit-identical to `si(x, 8192)`.

### 1.5 `append_payload(payload, bit_count)` (rsb:62-65)

Requires `len(payload) == ceil(bit_count/8)`; appends the low `bit_count` bits of `int.from_bytes(payload, "little")`. Bits of the last byte above `bit_count` are discarded. `append_payload(b"", 0)` appends nothing (used by the `append_actor_*` helpers with an empty prefix).

### 1.6 `append_fstring_ascii(value)` (rsb:67-72)

Requires ASCII, non-empty, no NUL, at most 240 characters (non-ASCII raises `UnicodeEncodeError`, the rest `ValueError`). Writes `b32(len + 1)` then the bytes plus a trailing `00`, all through `append_payload` (so it works at any bit alignment). Never emits an empty or UTF-16 FString.

### 1.7 Error behaviour

Every builder raises `ValueError` before writing anything if an argument is outside its guard. Exceptions to "ValueError": `build_starting_equippable_open(i)` raises `IndexError` for `i >= 7` (tuple index at rsb:716 runs before the guard in `starting_equippable_guids`); `build_pistol_auth_state_body` raises `KeyError` for an unknown state name; `append_fstring_ascii` raises `UnicodeEncodeError` for non-ASCII; `struct.pack("<f")` raises `OverflowError` for values outside f32 range; `round()` of a NaN or infinite yaw raises. The guards are validation only; none changes the encoding. The Rust port should return an error on the same conditions so that a bad stage fails loudly instead of sending garbage.

## 2. Vectors and rotators

### 2.1 `append_quantized_vector10(writer, location)` (rsb:78-96)

Used for actor spawn locations (pawn open, bots, projectiles).

```text
require 3 finite floats
c_i = floor(v*10 + 0.5) if v >= 0 else ceil(v*10 - 0.5)      # half away from zero; -0.0 counts as >= 0
require -2^31 <= c_i < 2^31
width = smallest w in 1..63 with -2^(w-1) <= c_i < 2^(w-1) for all three
b7(width | 0x40)
b{width}(c_x & (2^width-1)); b{width}(c_y & ...); b{width}(c_z & ...)
```

Compute `v*10` in f64 exactly as Python does (one multiply, then add or subtract 0.5, then floor or ceil). Because components are int32, `width <= 32`; the `width > 63` check (rsb:92) is unreachable.

### 2.2 Spawn rotation inside `append_dynamic_actor_header` (rsb:171-195)

```text
pk(actor_guid) pk(archetype_guid) pk(level_guid)
if spawn_location is None:
    b4(0)                                  # no location, rotation, scale, velocity
else:
    b1(1) b1(1) qv10(spawn_location)       # location present, quantized format
    yaw_short = round((spawn_yaw or 0.0) * 65536.0 / 360.0) & 0xFFFF
    if yaw_short != 0:
        b1(1) b1(0) b1(1) b16(yaw_short) b1(0)   # rotation present, pitch 0, yaw, roll 0
        b2(0)                              # default scale, velocity
    else:
        b3(0)                              # no rotation, scale, velocity
```

This is the yaw-only case of the general FRotator `SerializeCompressedShort` form `b1(any axis nonzero)` then, per axis pitch, yaw, roll, `b1(nonzero) [b16(short)]`, then `b2(0)`; range_projectiles.py:164-179 (`_append_spawn_header`, PROD with `ability_projectiles`) writes the general form with a pitch, so the Rust writer should implement the general form (other doc). Production yaws are real: range_bots.py:180 passes `bot.yaw = degrees(atan2(...))`.

Port pitfalls: Python `round()` is round-half-to-even (use `f64::round_ties_even`), the expression is `(yaw * 65536.0) / 360.0` in that order, negative results wrap through `& 0xFFFF` (-90 deg gives 0xC000), and 360 deg gives 0 (no rotation written). The vectors below include the exact .5 cases (0.5 -> 0, 1.5 -> 2, 2.5 -> 2).

## 3. NetGUID exports and actor-open bodies

### 3.1 Wire grammar

Derived from the flat Python sequences; the vectors are the authority.

```text
Exports    := b1(0) b32(count) ObjRef{count}          # b1(0): NetGUID exports, not NetField exports
ObjRef     := pk(guid) [ if guid != 0: b8(flags)
                         [ if flags & 1: ObjRef(outer) fs(name) [ if flags & 4: b32(0) ] ] ]
ActorOpen  := Exports pk(actor) pk(archetype) pk(level) SpawnInfo      # section 2.2
StaticOpen := Exports pk(actor)                                        # ch3 only
```

Flags used: 5 (path plus network checksum, checksum always 0) for anything being named, 0 for an outer that the client already knows (only the GUID is sent). The root outer is `pk(0)` with no flags byte. The export count is 1 in every builder in this file; other production modules export several objects in one block (range_abilities:184, range_bots:171 and range_projectiles:190 write `b32(2)`, range_attachments:140 writes `b32(len(assets))`; other docs), so the Rust `Exports` writer must take a list. A bunch whose body starts with `Exports` must have `has_exports=True` in its `BunchHeader`; every Python call site sets it consistently.

## 4. Content blocks, rep-layout payloads and RPC payloads

### 4.1 Content block grammar

```text
ContentBlock := b1(bHasRepLayout) b1(bIsActor) [SubobjRef if bIsActor == 0]
                pk(payload_bits) raw(enc(payload, channel_actor_guid), payload_bits)
SubobjRef    := pk(subobject_guid) b1(bStablyNamed) [DynamicTail if bStablyNamed == 0]
DynamicTail  := b1(0) pk(class_guid) b1(0) pk(outer_guid)
```

- Rep-layout data on the channel actor: `b1(1) b1(1)`. RPC on the channel actor: `b1(0) b1(1)`. Rep-layout data on a subobject: `b1(1) b1(0)`.
- `DynamicTail`: the first `b1(0)` has no confirmed name (hs:2794 "mystery 0-bit from writer", rsb:741 "class-ref selector"); the second is `bActorIsOuter = 0`, followed by the explicit outer (always inventory 60 here).
- Only the payload is content-transformed, and the seed is always the **channel actor's** NetGUID, also for subobject blocks (inventory and item slots on ch8 use 10, the state machine on ch9 uses 94, BombTeam and Money on ch6 use 6, ViewTarget on ch5 uses 4).
- A content block may follow an `Exports` block in the same bunch body (exports first).

### 4.4 RPC payload grammar

```text
RpcPayload := si(field_index, class_max_index + 1) pk(param_bits) Params
Params     := for each parameter: b1(1) ParamValue        # legacy per-parameter presence bit (connection flags @172 == 0)
```

Object parameter: `pk(guid)`. uint32: `b32`. Struct `FCharacterNetworkSerializationPackedBits`: `pk(bits) raw(bits)` (`build_packed_bits_struct`). TArray<struct> parameter (`ClientUpdateMultipleLevelsStreamingStatus`): `b16(count)` then each element's fields in order with no handles. RPCs without parameters write `pk(0)`. The whole `RpcPayload` is what gets content-encoded and wrapped by `append_actor_rpc_content_block`. One RPC per content block in all Python senders. Every body built in rsb and hs carries at most one content block, but other production bodies carry more: the smoke projectile open (range_projectiles.py:182-224; `cloudburst_state` always passes `movement_guid`, hs:1037-1041, reached from hs:1620 with `ability_projectiles`) is `Exports(2)`, the actor header, an actor rep-layout block, then a FiniteSpeedMovement subobject block, and the bot open (range_bots.py:160-195) is `Exports(2)`, the actor header and a BombTeam subobject block. The Rust body writer must allow `[Exports] [actor header] Block*` (other docs).

Guards of the RPC builders (all raise `ValueError`): `build_client_set_hud_payload` `0 <= field < max` and `1 <= guid <= 0xFFFFFFFF`; `build_input_ack_rpc_payload` `0 <= field < max`, both values uint32; `build_client_game_phase_begin_payload` `0 <= field < max`, phase 0..7; `build_move_response_rpc_payload` `0 <= field < max`; `build_client_set_view_target_payload` `0 <= field < max`, `1 <= guid <= 0xFFFFFFFF`, blend function `<= 0xFF`; `build_server_performance_rpc_payload` `0 < ms < 1000`; `build_client_update_multiple_levels_streaming_status_payload` 1..16 names, each starting `/Game/`. `build_client_restart_rpc_payload`, `build_client_goto_state_payload`, `build_client_flush_level_streaming_payload` and `build_client_update_range_settings_payload` have no explicit field guard (the last three fail only through `si` if `field >= max + 1`; goto-state's FString guard still applies).

## 5. Content transform: `encode_short_actor_rep_payload` (rsb:1131-1216)

Inverts the client's `FContentBlockReader::SerializeBits` (image 0x7FF738F94320). PROD everywhere, always with `source_bit_offset = 0`.

### 5.1 Contract

- Inputs: payload bytes `P`, bit count `n`, `source_bit_offset`, `actor_map_value` = channel actor NetGUID.
- Guards: `n >= 1`, `len(P) == ceil(n/8)`, `0 <= offset <= 6`; offset 0 requires `n >= 9`; offset != 0 requires `n == 9`. The smallest production payload is the 9-bit empty rep payload `b1(0) pk(0)`.
- Output: `ceil(n/8)` bytes; append with `raw(out, n)`.
- `_UNIFORM_BYTE_TRANSFORM` (rsb:1079-1083) is False in production; it is only set by `--move-ack-uniform-transform` (hs:4912-4914, DEAD). When False the 64-bit and 32-bit stages below run.

### 5.2 Seed and state (u32 `seed`, u64 `first`, `second`)

```text
M = 0x2545F4914F6CDD1D
mix(v, s) = M * ( v ^ ((s << 25) mod 2^32) ^ ((v ^ (v >> 15)) >> 12) )  mod 2^64     # v, s are u32
seed  = (actor_map_value ^ n) mod 2^32
first = mix(seed, seed)
second = mix((seed - 378250948) mod 2^32, (seed + 60) mod 2^32)        # 378250948 = 0x168BA6C4

advance():                                                              # after every wide, word and byte unit
    seed'   = ((first + second) mod 2^64) >> 32
    c       = second ^ first
    second' = (c ^ ((c << 14) mod 2^64) ^ rotr64(second, 9)) mod 2^64
    first'  = rotr64(c, 28)
```

### 5.3 Stages (offset 0)

```text
k = 0 (byte offset into P)
repeat n div 64 times:   out += le64(encode_wide(le64(P[k..k+8]), seed)); k += 8; advance()
if n - 8k >= 32:         out += le32(encode_word(le32(P[k..k+4]), seed)); k += 4; advance()
while k < n div 8:       out += encode_byte(P[k], seed); k += 1; advance()
if r = n mod 8:          out += (P[last] & (2^r-1)) ^ ((seed ^ 0x3C) & (2^r-1))
```

`encode_wide(x, s)` (rsb:1100-1123), all u64, `Sub8` = apply `wide_sbox` to each of the 8 bytes:

```text
a = Sub8(x)
b = (zext(rotr32(s, 2)) - 1 - a) mod 2^64
c = Sub8(b)
d = swap64(reverse_wide_bits(c))                 # extra swap vs the packet transform (rsb:1119-1121)
m = NOT64(zext(rotr32(s, 7)))                    # upper 32 bits are all ones (Python ~x & mask_64)
return swap64(d ^ m)
swap64(v) = ((v >> 1) & 0x5555555555555555) | ((v << 1) & 0xAAAAAAAAAAAAAAAA)
```

`encode_word(x, s)` (rsb:1086-1097), u32, `Sub4` = `word_sbox` per byte:

```text
a = Sub4(x)
b = (rotl32(s, 2) - 1 - a) mod 2^32
c = Sub4(b)
return invert_content_word_scramble(c, s)
```

`scramble_content_word(w, s)` (rsb:1030-1047), copy literally, intermediate in u64 because `4*(...)` and `16*high` exceed 32 bits before masking:

```text
sw32(v) = ((2*(v & 0xD5555555)) | ((v >> 1) & 0x55555555)) mod 2^32
mixed = sw32(sw32(w) ^ rotl32(s, 7))
high  = ((mixed >> 2) & 0x33030303) | ((4*(mixed & 0xF3333333)) & 0xFF0F0F0F)
low   = (((mixed >> 2) & 0x33333333) | (4*(mixed & 0xF3333333))) >> 4
folded = ((16*high) | (low & 0x0F0F0F0F)) mod 2^32
return sw32(byteswap32(folded))
```

`invert_content_word_scramble(target, s)` (rsb:1050-1072) solves the affine map by GF(2) elimination. Measured closed form (0 mismatches over 20,000 random `(target, seed)` pairs, and `scramble(1 << i, s) ^ scramble(0, s) == 1 << (31 - i)` for every bit): `scramble(w, s) == rev32(w) ^ scramble(0, s)`, so `invert(t, s) == rev32(t ^ scramble_content_word(0, s))`. Either implementation gives identical output.

`encode_byte(d, s)` (rsb:1165-1206): Python brute-forces the unique `wire` in 0..255 with `transform_byte(wire, s) == d` and raises if not unique. Only `s & 0xFF` matters and the map is a bijection for all 256 seed bytes (checked exhaustively). Closed form, verified against the brute force for all 65,536 `(seed byte, d)` pairs:

```text
S    = byte_sbox_inverse   (the table the client indexes at byte_7FF740171F90 + 256, rsb:1160-1163)
Sinv = byte_sbox
sw8(x) = ((x >> 1) & 0x55) | ((x << 1) & 0xAA);  rev8 = 8-bit bit reversal
o     = Sinv[d]
inner = (121*s - 1 - o) mod 256
fs    = rev8(sw8(Sinv[inner]))
wire  = sw8(fs ^ ((-61*s) mod 256))
```

Forward map (client decode, `rci._decode_content_byte` and rsb `transform_byte`): `fs = ((-61*s) & 0xFF) ^ sw8(wire)`; `shuffled = ((65793 * (((32800*fs) & 0x88440) | ((2050*fs) & 0x22110))) >> 16) & 0xFF` which equals `rev8(fs)` for all 256 inputs; `inner = S[sw8(shuffled)]`; `d = S[(121*s + ~inner) & 0xFF]`.

The decoder for client-to-server content is `rci.decode_content_payload` (rci:93-140); it is the exact inverse of this encoder with the same state machine.

### 5.4 DEAD offset path (rsb:1211-1216)

Only reached by `--encoded-empty-game-state-update-offset` (hs:2261). For `n == 9`, `offset` 1..6: `next = ((first+second) mod 2^64) >> 32`; `first_mask = ((seed ^ 0x3C) & (0xFF << offset)) >> offset`; `rem = 9 - (8 - offset)`; `last_mask = ((next ^ 0x3C) & (2^rem - 1)) << (8 - offset)`; output `((P_int ^ first_mask ^ last_mask) & 0x1FF)` as 2 bytes. Not needed in Rust.

## 7. Bunch frame: `BunchHeader` and `build_server_bunch_frame` (rsb:1505-1611)

### 7.1 `BunchHeader` (rsb:1505-1521)

Frozen dataclass, field order and defaults: `channel_index`, `channel_name_index`, `channel_sequence=0`, `is_open=False`, `is_close=False`, `is_reliable=True`, `replication_paused=False`, `has_exports=False`, `has_must_map=False`, `is_partial=False`, `partial_flags=0` (unused), `header_flag_4=False`, `close_reason=0`. Production always uses `channel_name_index=102` for actor channels; 255 is only used by the control-channel test vector (the handshake's own control replies copy the client's Hello header instead, hs:640-694).

### 7.3 Validation (rsb:1540-1563)

`0 <= server_sequence, acked_client_sequence < 0x4000`; `0 <= ack_history_mask <= 0xFFFFFFFF`; `0 <= stateless_header < 32`; `len(receive_key) == 32`; channel index and name index `<= 0xFFFFFFFF`; not both open and close; `is_partial`, `has_must_map`, `header_flag_4` rejected; close requires reliable; `0 <= close_reason < 15`; reliable requires `channel_sequence < 0x1000`; unreliable cannot open; `body_bit_count < 8192`. In addition `transform_short_packet` rejects a decoded total above 8192 bits, so a reliable bunch with 1-byte channel and name can carry at most 8064 body bits. There are no partial bunches in the Python.

### 7.4 Encryption and framing (rsb:1606-1611, hs:402-425)

```text
decoded, n = writer.to_bytes(), writer.bit_count
t   = transform_short_packet(decoded, n, counter=0)              # section 8
out = wrap_gcm(t, "", n, receive_key)
T   = 32 + 6 + 64 + n + 8                                       # = n + 110
V   = (int_le(out) << 38) | (stateless_header << 32) | (1 << T)
frame = V as little-endian bytes, length (T + 8) div 8          # = (n + 118) div 8
```

`wrap_gcm(payload, player_key, bit_count, receive_key_override)`:

```text
r = n & 7
plaintext = t; if r: plaintext[-1] = (plaintext[-1] & (2^r-1)) | ((0xCC << r) & 0xFF); suffix = 0xCC >> (8 - r)
               else: suffix = 0xCC
nonce = le32(0) || le32(0x7908CBDD)          # 8 bytes: a 64-bit GCM IV, J0 derived through GHASH
ciphertext, tag = AES-256-GCM(key = receive_key, nonce, plaintext, aad = empty)
out = le32(0) || tag[0..4] || ciphertext || suffix
```

So frame bytes 0..3 are zero, bits 32..37 carry the client's echoed stateless header (bit 37 always 0 because of the `< 32` guard), the GCM counter (always 0) and 4-byte tag start at bit 38, the 0xCC trailer sits immediately after the `n` payload bits (its low part encrypted inside the last ciphertext byte when `r != 0`), and the terminal 1 bit follows. A Rust GCM implementation must accept a 64-bit IV (for example `aes_gcm::AesGcm<Aes256, U8>`); a 96-bit-nonce API produces different bytes. `aes_gcm` only allows tag sizes 12..16, so encrypt detached with the default 16-byte tag and keep its first 4 bytes (a truncated GCM tag is the prefix of the full tag). The Python reuses nonce counter 0 for every server packet; keep it for bit equality (open question 4).

Live cross-check: the logged frame lengths in `runtime/responder_*.out` are 119 bytes for the pawn open (`sent_wushu_pawn_probe_length`), 34 for the GameState bool, 35 for ClientRestart and 24 for every session ack, with no other value logged for any of them (occurrence counts at verification time: 110, 110, 104 and 676,620); vectors F1 and F2 below and `(n + 118) div 8` reproduce them.

## 8. `range_udp_transform.py` (packet transform)

Used on the server send path only as `transform_short_packet(decoded, n, 0)` (rsb:1607, hs:590, 633, 690; hs:4554 is the DEAD `derived_key_gcm` challenge). `inverse_short_packet(plaintext, n, counter)` decodes client packets with the client's counter (hs:472); its algorithm and vectors are specified in 01_transport.md section 8.3 and 06_client_decode.md section 2.3, not here. The S-box tables are in section 5.5.

```text
M = 0x2545F4914F6CDD1D
initial_state(counter):
    c  = counter mod 2^32
    bf = (c + 0x024EDCC0) mod 2^32                       # 38722752
    mf = bf ^ (((bf ^ (bf >> 15)) >> 12) mod 2^32)
    mf ^= ((c - 64) << 25) mod 2^32                       # c - 64 wraps (Python negative int), use wrapping_sub
    ms = c ^ ((c << 25) mod 2^32)
    ms ^= ((c ^ (c >> 15)) >> 12) mod 2^32
    return first = M*mf mod 2^64, second = M*ms mod 2^64, selector = c
advance_state(first, second):
    x = first ^ second
    first'    = (x ^ ((x << 14) mod 2^64) ^ rotr64(first, 9)) mod 2^64
    second'   = rotr64(x, 28)
    selector' = ((first + second) mod 2^64) >> 32
transform_short_packet(p, n, counter):        # requires 0 < n <= 8192 and n <= 8*len(p)
    k = 0; (first, second, sel) = initial_state(counter)
    n div 64 times:  a1, a2, a3 = rotr32(sel, 1), rotr32(sel, 3), rotr32(sel, 5)
                     v = le64(p[k..]); v = Sub8(v + a1); v = Sub8(v + a2); v = reverse_wide_bits(v - a3); v = Sub8(v)
                     (all mod 2^64, Sub8 = wide_sbox per byte); store; advance; k += 8
    (n mod 64) div 32 times (0 or 1): same with rotl32(sel, 1/3/5), mod 2^32, word_sbox, and rev32 (full 32-bit reversal)
    full bytes:      v = byte_sbox[(v + 11*sel) mod 256]; v = byte_sbox[(v + 51*sel) mod 256]
                     v = (v - 27*sel) mod 256; v = byte_sbox[rev8(v)]; store; advance; k += 1
    r = n mod 8:     p[k] ^= (2^r - 1) & (sel ^ 0xC0)
reverse_wide_bits(v):  reverse the bit order inside each 16-bit lane, then rotr64(32); an involution (rut:37-43)
```

## 9. Production use map

### 9.1 Where each production body is sent

`B` = `initial_actor_channel_sequences[source]` (section 10). Setup-chain bunches are sent from the session-ack branch (hs:2172-4407). ## 13. Port pitfalls checklist

1. Python integers are unbounded; every mask in the Python is load-bearing. Use u64 (u128 where a product or shift can exceed 64 bits before masking) and wrapping arithmetic; for example `~rotr32(s,7) & mask_64` sets the upper 32 bits (5.3).
2. `round()` is half-to-even; the quantizer is half-away-from-zero. Different functions on purpose (2.1, 2.2).
3. `si()` width depends on the value; never precompute it from `value_max` alone.
4. The content transform seed is the channel actor GUID XOR the payload bit count, including for subobject blocks.
5. `encode_short_actor_rep_payload` requires `n >= 9`.
6. `append_payload` drops bits above `bit_count` in the last byte; payload bytes from builders already have those bits clear.
7. Every reliable bunch has `bControl = 1` and a hardcoded name; one bunch per datagram; no partial bunches; the decoded packet must stay at or below 8192 bits.
8. GCM uses an 8-byte IV, 4-byte tag, counter 0, direction constant 0x7908CBDD for server-to-client (client-to-server uses 0x31ED27AB with the packet's counter, hs:464).
9. f32 values come from Python `struct.pack("<f", f64)`, which rounds to nearest even like Rust `as f32` (Python raises `OverflowError` where Rust would produce infinity; no production value is near the f32 limit).
10. The controller open has a trailing `b8(0)` after the actor header; no other actor open has it.
11. `build_object_property_payload` (GUID <= 0xFFFF) and `build_bool_property_payload` (handle <= 63) guards are validation only.

## 14. Open questions

1. `ClientSetHUD` field index and class max are resolved live through the client's FClassNetCache (hs:3784-3791, thunk RVA 0x4B6B340); every logged run produced 52/178. The Rust server needs either these constants or an oracle lookup.
2. NumUltimatePoints is read live from pawn+0x14F4 (hs:1836); the logged value is 8. Same choice as 1.
3. BombTeam TeamNumber width 8 (`bomb_team_number_bits`, hs:3594-3596 "codex to confirm") is what production sends, but the width was never confirmed against the live NetSerialize.
4. The server reuses GCM nonce counter 0 for every packet. Whether the client accepts a counter that increments is untested; keep 0 for bit equality.
5. Python always writes `bHasServerFrameTime = 0` and jitter 0. Sending a real frame time for the 128 tps server would change the header bits and is untested.
6. The first bit of `DynamicTail` (value 0) is unnamed in the code; its meaning is unverified.
7. Packing several bunches into one datagram would be valid UE but would not be bit-identical to the Python; decide whether golden equality applies per bunch or per datagram.
